Technical Progress and Findings Report

Modeling Material Degradation with Fourier Neural Operators and Auditing Feature Causality

Fudail ibn Umar Farooq Khawaja (Purdue University) and Muhammad Ahmad (Thayer School of Engineering, Dartmouth College). Both authors contributed equally.

Status Phases 0–5 complete, all gates passed Date 2026-07-12 Scope Phases 0–1 in a separate frozen repository; this repository covers Phases 2–5

1Executive Summary

This project set out to answer a deceptively simple question in a setting where the answer can actually be checked: when a neural network learns physics, does it rely on the causal drivers of the system, or on spurious correlates? It is the "wolf vs. snow" shortcut-learning problem transplanted into computational physics, where synthetic data provides what photographs never can: a ground-truth answer key, because we decide which factors enter the governing equations.

The project's full synthetic arc is complete. All five build phases passed their pre-registered exit gates:

2Phase-by-Phase Breakdown

Phases 0–1 · Environment, Problem Statement, and Diffusion Warm-up Complete

(a) Objectives

Reproducible environment; a written problem statement separating the three claims; de-risk the ML pipeline on the easiest target (2D heterogeneous diffusion) before the physics gets interesting.

(b) Deliverables

Single-script pipeline: py-pde diffusion solver, Gaussian-random-field (GRF) input sampling, 3,000-sample dataset with a held-out correlation-length band, trained FNO, evaluation suite, problem-statement document. These artifacts live in the frozen Phases 0–1 repository and are not included here.

(c) Findings and decisions

GRFs adopted as the principled input distribution (controllable correlation length and spectral decay, giving clean OOD holdouts). The FNO recipe (16 modes, 64 hidden channels, 2.4M params) reached 1.23% ID and 1.20% OOD relative L2, establishing the architecture reused in every later phase.

Phase 2 · Allen–Cahn Simulator and FNO Surrogate Gates 2a + 2b

(a) Objectives

A trustworthy degradation simulator (∂u/∂t = M(x)·(ε²∇²u + u − u³ + g)), a surrogate accurate enough to stand in for it, and a generator≠validator independence check.

(b) Deliverables

The modular fnocausal package: config and provenance hashing, per-sample rng streams, primary SBDF2 pseudo-spectral solver, explicit-RK4 validator solver, py-pde cross-check, Nyquist-correct Fourier resampling, physics metrics, shared training loop, 6-check verification suite, a 6,000-sample dataset (64×64, T=1) plus a full validator test set re-solved with the independent scheme at 128², dt/4, and 16 unit tests.

(c) Findings and decisions
  • Scheme choice was measured, not assumed. First-order semi-implicit stepping missed the cross-scheme tolerance (1.8×10−3), so the solver was upgraded to second-order SBDF2 (7×10−5 at dt=2.5×10−3).
  • Solver verification is load-bearing. Energy monotonicity, the shrinking-circle law d(R²)/dt = −2ε² (0.8% deviation), coarsening scaling, dt and grid convergence, and three-way scheme agreement all passed before any training data was generated.
  • Gate 2b. ID test 1.52%; independent-scheme targets 1.53% (the schemes agree to ~9×10−4, so the surrogate error budget is entirely model, not solver); held-out ε-band 1.26%.

Phase 3 · Autoencoder Featurization Gate 3 (revised)

(a) Objectives

A compact latent representation z of the material state as the analysis substrate for the causal audit. The FNO always operates on full fields, so the AE is instrumentation rather than pipeline.

(b) Deliverables

Convolutional autoencoder; a 10-model sweep (2 field variants × z ∈ {8…128}); pixel-reconstruction and functional-fidelity reports with figures.

(c) Findings and decisions

The planned pixel-L2 gate (≤5%) is informationally impossible for saturated two-phase fields: error is dominated by interface placement (rel-L2 ≈ √(4δL)), so 5% would demand ~0.01-cell interface accuracy from any latent. The gate was re-anchored on what the audit requires, preservation of physical observables. At z=128: severity R² 0.975, interface-length R² 0.932, pixel 12%. The pixel curve remains on the record.

Phase 4 · Spurious-Structure Injection, the Answer Key Gates 4(i)–(iv)

(a) Objectives

A dataset where a nuisance factor S is provably non-causal and a driver C is provably causal, with training environments where S correlates with the outcome and evaluation environments where the correlation weakens, breaks, or reverses.

(b) Deliverables

An 8,000-simulation pool (nucleation-growth regime, tilted well g=0.3, hidden mobility M(x)=m·GRF); seven environments (train ρ ∈ {0.95, 0.8}, control ρ=0, eval ρ ∈ {0.95, 0.5, 0, −0.95}); a per-sample answer-key CSV; five trained models, namely biased, control, and oracle FNOs plus two severity heads, together with the biased-environment AE audited in Phase 5.

(c) Findings and decisions
  • The load-bearing insight: hide the causal driver. If a model sees all causal inputs, the target is deterministic in them and a competent network ignores any nuisance, leaving no shortcut and no experiment. With M(x) hidden, the nuisance genuinely carries information in biased environments, so the Bayes-optimal predictor must use it, which guarantees both adoption and collapse under reversal. Exactly the wolf/snow structure.
  • Monotonicity by construction, not luck. Traveling-wave analysis gives front velocity V = M·ε·3g/√2 and critical radius R_c = ε√2/(3g), both independent of m. With g=0.3 and ε=0.03 this puts R_c ≈ 0.047, so seeding all nuclei in [0.07, 0.13] makes severity monotone in the hidden amplitude for every sample (confirmed 20/20 in matched interventions; severity spread 0.04–0.88, zero saturation). The tilt also stays below the spinodal g* = 2/(3√3) ≈ 0.385, above which the −1 phase would destabilize.
  • Adoption confirmed. Biased beats control on held-out same-distribution data (FNO 0.250 vs 0.351 rel-L2; head 0.038 vs 0.083 MAE) while the oracle sits at 0.0077, reproducing the full designed ordering.

Phase 5 · The Causal Audit Gate 5, 21/21

(a) Objectives

Quantitatively separate causal from spurious reliance with multiple corroborating methods, checking every verdict against the Phase 4 answer key.

(b) Deliverables

An audit orchestrator over five analysis modules; a scorecard CSV recording, for every check, the expected pattern, the measured value, and the verdict; an auto-generated conclusions document; five figures.

(c) Findings

All five diagnostics agree with the answer key across 21 gate-counted checks, as summarised below.

3Technical Challenges and Explanation Report

C1Long-horizon operator learning is chaotic

The first surrogate, trained on a T=4 horizon, memorized the training set (train MSE 5.5×10−4) yet generalized at 17%, with best validation at epoch 6 of 100. A T=4 one-shot map spans an entire coarsening cascade whose merger outcomes depend sensitively on the input. Resolution: horizon shortened to T=1 where the operator is well-conditioned; longer horizons via autoregressive composition are future work. Documented as a config-level decision.

C2A hidden-parameter bug that later became the experiment

Even at T=1, 11% error with instant overfitting. Root cause: the PDE parameter ε was not a model input and is not inferable from the other channels, so the target literally was not a function of the inputs. Resolution: ε fed as a constant channel (standard parametric-FNO practice), collapsing the error 60× to 1.5%. Instructive symmetry: the same hidden-variable structure that was a bug in Phase 2 is deliberately constructed in Phase 4, where its training signature reappears by design.

C3Physics checks mis-specified for a finite box

The textbook coarsening exponent (ℓ ~ t1/2) is unmeasurable in a unit box, since no scaling decade exists and the structure-factor length is biased by the Porod tail. Resolution: the check was restated in the reachable regime as the differential form of the same law (ℓ² linear in ε²t; measured R² 0.98, slope ≈ 9ε²) with an interface-density length measure.

C4Nyquist handling in spectral resampling

Naive Fourier truncation and zero-padding broke the exact resample round trip (2.6% error) by mishandling the ambiguous Nyquist bin. Resolution: Nyquist-splitting resampling matrices, after which the round trip is exact and validator targets are alias-free.

C5The compute wall

Single-threaded NumPy solves projected ~14 h for one dataset plus its validator set. Resolution: float32 CUDA backends for both solvers (~100×, 25 min total), with the float64 NumPy path retained as the verified reference and cross-backend agreement unit-tested (<10−4). This also made the audit's 1,280 extra Sobol simulations cheap.

C6Ecosystem breakage

SALib 1.5.1 passes problem names into pd.unique, which pandas 3.0 no longer accepts for plain lists. Resolution: a one-line fix (names as ndarray), noted for future SALib use.

C7Two audit checks were initially mis-formalized

(i) Requiring the multivariate probe's causal coefficient to be stable across environments is not what ICP predicts: with a shortcut available, a full-representation fit legitimately shifts weight from causal to spurious directions, and that reweighting is itself evidence of adoption. Replaced with ICP-correct univariate score probes, which pass cleanly. (ii) The IRM check tested a coefficient ratio rather than IRM's operative promise, out-of-environment risk; it was re-formalized with λ selected on an independent environment and remained negative, hence the documented informational finding. Both re-formalizations are explained inline in the audit code, and thresholds were never adjusted to fit results.

4Project Velocity and Known Limitations

Velocity. Phases 2–5, comprising the solvers, a roughly 30-module package, the full model suite, and the five-diagnostic audit, were delivered in three working sessions, with all computation fitting a single consumer GPU (RTX 2070). The exit-gate discipline caught every significant defect before it could contaminate downstream phases.

Quality posture. 16 unit tests, all green. Every run is config-driven and seeded; every results CSV carries run_id, config_hash, and a claim tag. Numerical work is split into a verified float64 reference path and an agreement-tested float32 CUDA bulk path. Per-sample SeedSequence streams make any sample or intervention twin exactly regenerable from two integers.

Known limitations, in priority order:

  • Single-seed results. All headline metrics come from one master seed per phase. Cheap to fix now: a 5-seed replication with dispersion estimates should precede publication claims.
  • No continuous integration. Tests and gates run manually; a minimal pipeline (pytest plus linting on push) would protect the reference solvers from silent regression.
  • Single-direction ablation. A small-subspace variant is specified but unimplemented, and is worth adding even though the single-direction result passed decisively.
  • Surrogate horizon. The Phase 2 surrogate covers T=1; autoregressive composition to longer horizons is unvalidated.
  • Mitigation is post-hoc only via latent ablation; training-time mitigation was probed only through the inconclusive IRM linear probe.
  • Portability and structure. Some paths assume Windows, and the audit script is long (~450 lines) and could be split per-diagnostic.

5Next Steps and Recommendations

  1. Phase 6a, cross-PDE replication (highest priority). Repeat Phases 4–5 on Fisher–KPP (∂u/∂t = D∇²u + ru(1−u); traveling fronts, different dynamical character). A method that only works on Allen–Cahn is overfit to one equation, which is the clearest outstanding weakness, and the infrastructure was designed for this.
  2. Phase 6b, robustness sweeps. Re-run the audit under observation noise, sensor sparsity, and resolution changes; confirm the verdicts survive realistic measurement conditions.
  3. Multi-seed replication. Five master seeds across the headline metrics, reported with dispersion (under a day of compute at current throughput).
  4. Mitigation experiment. Compare naive training against an invariance-trained or ablation-regularized model, upgrading the project from diagnosing shortcut learning to fixing it. Given the IRM probe result, prioritize representation-level interventions over IRMv1-style penalties.
  5. Phase 7, write-up. Assemble the paper around the three-claims framing; figures and CSVs already carry provenance tags. The negative IRM result and the documented check re-formalizations belong in the paper, since they strengthen the methodology narrative.
  6. Housekeeping. Stand up CI, add linting, and write a results-directory README mapping each CSV to the claim it supports.
